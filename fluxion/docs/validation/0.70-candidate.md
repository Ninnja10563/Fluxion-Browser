# 0.70 candidate validation

Release approval requires a complete passing native macOS run, followed by
inspection of its reports and screenshots. Linux regression checks alone do
not establish macOS behavior. Failed candidates below were not published.

## First candidate

[35059418893](https://github.com/Ninnja10563/Fluxion-Browser/actions/runs/35059418893)
built `806ba7ec557bf665f0d400d768f0b690cc5d52b7`. Application build, universal
architecture, signature and base browser integration passed. Five gates failed:

- Migration reached the real wizard, but its driver used an obsolete native
  event API. The driver now uses the pinned runtime's widget event interface.
- Fullscreen capture occurred during the OS transition; fractional coordinates
  also missed the one-pixel reveal target. The verifier now waits for a stable,
  active, painted window and requires trusted input at the actual target.
- The transfer test assumed the first context-menu item was a command, but the
  new container submenu occupied that position. Containers now follow Duplicate,
  preserving the existing first command and all native menu behavior.
- Last-window tabs restored, but the test required a user preference bit that
  Gecko can legitimately remove when its value equals the default. The explicit
  homepage-to-restore scenario still requires effective startup value 3, while
  recording actual provenance. Startup opt-outs remain mandatory.
- The default-browser status had an empty native accessible description when
  its referenced text also had `role=status`. Removing that conflicting role
  retains live announcements and restores the actual accessible description.

The branding gate passed through a direct popup invocation, but screenshot
inspection showed the popup at the window origin. The next gate requires
interaction with the painted native identity control and correct anchoring;
that first pass is not evidence of correct popup placement.

## Second candidate

[35060400923](https://github.com/Ninnja10563/Fluxion-Browser/actions/runs/35060400923)
built `82b6d41beb473df327475bc1450822abbdd544f2`. All 1,062 regression checks
passed. Every mandatory native gate except migration and branding passed.
Neither a DMG nor a release was produced.

- Migration opened, cancelled and reopened the standalone wizard, then reached
  the real macOS file chooser. The keyboard helper refused the HTML fixture
  because it permitted only the earlier upload fixture. A separate compile-time
  allowlist now permits exactly the owned migration fixture; arbitrary paths
  remain rejected. Compiled positive and negative path tests cover both builds.
- Branding's stronger identity-control test could not find a hit-testable
  anchor after New Tab, custom Settings and HTTPS navigation. The next verifier
  uses real owned-process Command-L/Escape to finish address editing, with
  before/after focus, URI, proxy and anchor diagnostics. It does not force
  native security flags or directly manufacture a popup.

Native fullscreen entered at 1920×1080 with a stable painted window, accepted
trusted top-edge mouseover and Command-L/Escape, then returned to its 1280×873
window with actual eight-pixel content clipping. Reviewed hidden, revealed and
restored screenshots show no OS-transition ghost. The transfer gate passed all
ten checks. Settings passed native names/descriptions for 36 controls across
six sections, plus narrow 320/600px layouts.

All six last-window stages passed: Flow-created pinned and normal pages across
workspaces restored with the selected page and metadata; explicit startup
choice 1→3 survived normal quit/relaunch without test-forced saving or pre-close
state collection. Default-valued preference provenance was recorded rather
than assumed. Startup choices 0/1, private exclusion, external-request merging,
repeated checkpoints and native undo records retained their independent gates.
Both the native close-tab command and the Flow close control retained other
workspaces' hidden pages. This does not reproduce the user's original 0.69
profile or establish a physical red-window-button audit.

Real browsing verified container account separation: the newly opened
container remained unauthenticated while the original page retained its login
after reload. Default-browser verification intercepted the OS-changing call;
it proves explicit native delegation and accurate status, not acceptance of an
actual system-default change. The runner's default browser was not changed.

## Third candidate

[35061354459](https://github.com/Ninnja10563/Fluxion-Browser/actions/runs/35061354459)
built `5b4a83b0b94b18ffed92286e87216ccd8435ee53`. Local preflight passed all
1,064 tests with no failures or skips. The migration gate now passed all five
checks: native wizard invocation, cancellation, actual macOS HTML-file import,
Unicode titles/folder retention and unchanged existing bookmark identity and
placement.

Branding still failed its strict identity-control gate. Diagnostics show the
HTTPS page selected and loaded, with Settings hidden, but its provisional
`userTypedValue` and invalid page-proxy state remain. Both native identity
anchors have zero dimensions. Trusted Command-L and Escape arrived, but the
first Escape only dismissed address suggestions; it did not revert the
provisional URL. The next diagnostic records native navigation events and uses
a second real Escape for Gecko's native revert path. No product security flags
are forced, and popup anchoring remains required. The cause of the original
programmatic Settings-to-page transition is not established.

Every other mandatory native gate passed, including the six last-window
stages, import, native accessibility and privacy checks. Packaging remained
blocked by branding; nothing from this run was released.

## Fourth candidate

[35062000814](https://github.com/Ninnja10563/Fluxion-Browser/actions/runs/35062000814)
built `315529a68e28c83df7f1008f0d19235783312345`. All 1,065 local regression
tests passed with no skips. The branding gate passed and actual captures were
reviewed. The identity anchor is at (420.717, 8), size 28×28; the native panel
starts at (421, 36), directly beneath it. The transparent F, Fluxion status,
secure-connection row, enabled tracking-protection toggle and Privacy Settings
control remain visible. The default-browser row is aligned and readable; its
intercepted request leaves the runner's actual default unchanged.

Diagnostics preserve the unresolved transition: the programmatic tab was
created while the Settings content deck was hidden; LOCATION/LOADED observations
retain the provisional URL and report no started load, with no START/STOP
callbacks recorded by this observer. The first trusted Escape dismisses
suggestions; the second invokes native reversion, clears the typed value and
restores a valid proxy and visible identity control. This proves native revert
and branded popup behavior, not the cause or repair of the initial transition.
Quit wording is verified through actual native localization; the test does not
accept a quit dialog or the OS default-browser confirmation.

Every mandatory native gate, universal architecture/signature verification,
DMG packaging and artifact upload passed. Only automatic publication was
skipped; the verified artifact was subsequently promoted without rebuilding.
All six final last-window stages passed 26 checks with expected lifecycle
counts, no duplicate/extra closed records and no private records. The frame
gate passed 18 checks; stationary-pointer trailing-close settling was 97.7ms
in this CI sample. Product chrome passed 17 checks. Actual security, default-
browser, colour-picker and Focus navigation captures were reviewed. This is
not a physical-M3 benchmark, an imported-user-profile audit, or completion of
the original roadmap. Publication is recorded in
[release provenance](../../release/provenance/v0.70.0-preview.1.md).
