# Fluxion 0.56 sidebar-sizing candidate

This is candidate evidence, not release provenance. No 0.56 DMG has been
published; a complete successful release run is still required.

## Implementation and local evidence

The candidate adds a saved 180–420 pixel sidebar width (232 default), a
keyboard-accessible separator, pointer preview/commit/cancel, a draft-safe
Appearance input and Reset action, cross-window preference propagation, and
responsive width limits that do not overwrite the preferred size. Compact and
Focus rails keep their separate 44/3 pixel geometry. Named container queries
adapt Settings and Library to the actual space remaining beside Flow.

All 598 local tests passed on source
`92f5366314622dc5f62d6ed962a995711b4f0c89`. The shipped controller is executed
in tests for trusted-target validation, pointer capture, cancellation, stale
frame rejection, shared preference changes, no-op gestures in narrow windows,
keyboard direction, focus recovery and observer cleanup. Preview frames do not
save preferences; release saves once. Final geometry resolves before width
transitions resume, and ARIA bounds reuse the pre-write width measurement.

Settings tests execute the shipped script and check valid/invalid numeric
editing, Reset, shared values, draft preservation, Escape and unload. These
tests do not prove native layout or actual pointer capture by themselves.

## First packaged run

[Diagnostic 34519789082](https://github.com/Ninnja10563/Fluxion-Browser/actions/runs/34519789082)
used source `0c734d410b5045642d0bffcc91a08af3a650ba35` and passed its 597 local
tests. The new sidebar gate failed before pointer input because its test driver
called `window.windowUtils.sendMouseEvent`, which is unavailable in the locked
runtime. The report had already verified Settings changes/Reset, cross-window
geometry and native macOS Home/Right/End/RTL-Right resizing.

The failure was corrected against Mozilla's exact
[Firefox 155.0.1 Window interface](https://github.com/mozilla-firefox/firefox/blob/FIREFOX_155_0_1_RELEASE/dom/webidl/Window.webidl#L643)
and its
[EventUtils mouse router](https://github.com/mozilla-firefox/firefox/blob/FIREFOX_155_0_1_RELEASE/testing/mochitest/tests/SimpleTest/EventUtils.js).
The verifier now uses `Window.synthesizeMouseEvent`, with actual Gecko hit
testing and pointer capture still required. This is Gecko-routed input, not
physical OS pointer movement. Key input uses exact-owned-PID System Events.
The driver records coordinates and observed pointer targets for failures.

No failed or diagnostic-only artifact is eligible for release promotion.

## Current native verification

[Diagnostic 34520292127](https://github.com/Ninnja10563/Fluxion-Browser/actions/runs/34520292127)
passed on `92f5366314622dc5f62d6ed962a995711b4f0c89`: 598 regression tests
and every native diagnostic gate. Sidebar evidence records three trusted
Gecko-routed pointer starts on the separator, actual pointer capture,
release-to-save, native macOS Escape rollback, and Focus-overlay resizing
without reducing webpage width. Native Home/Right/End and RTL direction checks
also passed.

At a 580 pixel browser width, a saved preference of 420 displayed as 260,
preserving 320 pixels for the Settings and Library surfaces. Measured input,
Reset, Library search and content bounds remained inside those surfaces.
Both seed and clean-relaunch health reports passed, with actual, preferred
and effective widths all 318 after relaunch. The actual Appearance screenshot
was inspected for alignment and visible controls.

This does not establish physical OS pointer dragging, assistive-technology
usability, or high-refresh-rate performance. A full release staging run,
including packaging and anonymous About update discovery, is still required.
