# Fluxion 0.59 Browser Memory privacy candidate

Status: native staging in progress; not published.

## Motivation and scope

The previous policy rejected `/account` but allowed `/%61ccount`, even though
servers can route both to the same sensitive page. Indexing and result filters
shared that raw-path check. Tightening only the filter would leave previously
extracted text and vectors in the enriched database.

The shared policy now conservatively decodes paths for classification only.
New evidence is checked at extraction boundaries and again at store insertion.
Existing enriched evidence is swept before the first connection is exposed,
including non-private startup with Memory disabled. Excluded native vectors
retain their established content-free sentinel treatment; ordinary Places
history is not deleted.

## Required evidence

- Encoded letters, separators, nested escapes and malformed-input policy tests.
- Shipped runtime extraction and all partial/final result-source filtering.
- Transactional enriched text/vector cleanup, safe-neighbor retention,
  startup failure isolation, bounded keyset batches and stale-work invalidation.
- Actual native vector-byte scrubbing and enriched SQLite cleanup on macOS.
- Two-launch legacy-profile verification with Memory disabled: startup alone
  deletes excluded evidence while retaining safe vector bytes and Places visits.
- Full release staging, including all existing browser gates and actual
  anonymous update discovery, before promoting the exact tested DMG.

## Limits

Sensitive-route detection remains heuristic. Category exclusions and broader
resource/platform-accessibility work remain unfinished. Logical database
deletion does not establish forensic erasure from media or backups. Synthetic
vectors test storage/privacy behavior, not model inference quality.

## Bounded cleanup follow-up

Initial staging [34533591181](https://github.com/Ninnja10563/Fluxion-Browser/actions/runs/34533591181)
uses `53ee4280ad8c910d02eb474a6a2df4eeca4fc80f`. While it ran, a local
performance check found repeated exclusion-list normalization within a batch.
The candidate now prepares the same immutable policy once per 256-row batch,
with differential policy and snapshot-isolation tests. A 520-row regression
requires three prepared predicates rather than 520 normalizations.

On local Linux ARM64 Node 24.19, seven samples of 256 safe URLs against 200
exclusions measured median 193.00 ms with the original per-page normalization
and 11.92 ms with a prepared predicate (including preparation). Decisions were
identical. This is a policy microbenchmark, not macOS startup latency or total
browser performance. Combined code requires a new full staging run; the initial
run alone cannot qualify the later source for publication.

The encoded-sensitive native vector became a content-free sentinel while its
safe same-host neighbor retained its bytes and both Places visits survived.
Legacy enriched sensitive text/vector counts became 0/0, with safe counts 1/1.
A real second launch, with Memory still disabled, independently observed
sensitive text/vector removal through read-only SQLite; safe content/vector

Two unrelated gates failed, so no DMG was packaged or published:

- Library pagination/search/routes succeeded, but its menu remained open after
  the owned OS Escape request, with no recorded key/popup event. All recorded
  focus flags remained true. This does not establish a focus-restoration defect
  because the dismissal handler never ran. The next diagnostic will distinguish
  processed menu input from injection acknowledgements before testing Escape.
- The actual anonymous About GET received HTTP 403, remaining 0, reset
  `1789078405` (2026-09-10 22:13:25 UTC). No credentials/cookies/referrer or asset
  requests were sent. No release-discovery retry is allowed before that reset.

Follow-up also rejects a 201st distinct domain before changing preferences or
cleanup, instead of silently truncating it and reporting success. Settings
submits the complete list for validation; normalized duplicates remain valid
at capacity. Native sweeps share the prepared policy optimization.

The Library driver now sends one owned OS ArrowDown and requires both its
injection receipt and a fresh trusted activation of an enabled item belonging
to the exact popup. Only then does it request Escape. Native dismissal and
anchor-focus requirements remain unchanged, with no retries, forced selection
or programmatic hiding accepted as proof. Reports include native-menu status,
both acknowledgements and observed popup transitions. Both workflows retain
the Library's full verification log/report even on failure.

All 665 local regressions pass for the combined candidate. A macOS diagnostic
can verify it without making another anonymous update request during the
known quota window; publication still requires subsequent full staging.

## Second full staging: dialog initialization race

[34536370341](https://github.com/Ninnja10563/Fluxion-Browser/actions/runs/34536370341)
tested `d3575d434e07d835eca36add6bff6d394db83139` after the cooldown.
All 665 tests and all independent native gates passed, including both Memory
privacy gates and the Library's owned OS input check. About made one actual
anonymous GET and received HTTP 200, with no asset request.

The broad integration gate failed before native sanitizer cancellation could
be exercised: its verifier called `dialog.getButton()` at attempt 0 while
`sanitize_v2.xhtml` was still loading. Gecko had exposed the custom element
method but had not initialized its internal button map. The dependent Memory
grounding fixture correctly waited for cancellation evidence and timed out.
This is evidence of premature test access, not evidence that the product's
native cancellation failed. No DMG was packaged or published. A readiness fix
must preserve the actual native surface and cancellation assertions, and the
corrected source must pass a new full staging run.

The follow-up waits for `readyState === "complete"` before native button
access and requires the exact locked-runtime sanitizer document URI. It keeps
the existing bounded readiness wait, actual category/action checks and native
cancel-result requirement. Seven shipped-verifier regressions include loading
and interactive XUL prototypes, bounded initialization failure, immediate
reporting of initialized getter exceptions, wrong-document rejection and
non-cancel outcomes. No product sanitizer behavior or release gate was removed.
