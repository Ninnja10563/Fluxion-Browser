# Fluxion 0.60 candidate validation

0.59 is published. This candidate integrates flat-tab structural reconciliation
and packaged-app version validation from `perf/flow-reconcile`. It retains the
0.59 privacy policy and corrected native sanitizer readiness gate.

## Intended behavior

Flat same-workspace tab opening, closing and reordering keep unaffected native
Flow rows and their controls connected. Pin-role changes replace the affected
row, not its neighbors. Native order, independent pin/tree keyboard entries and
owned close/audio focus remain consistent. Single moves use one necessary DOM
relocation; adjacent swaps may relocate either equivalent neighbor. Grouped,
split and cross-workspace projections keep their full-render fallback.

This does not virtualize the list: authoritative state reads remain O(N), with
O(N log N) reorder planning. Mutation/focus tests are not physical pointer-input
latency or sustained high-refresh-rate evidence.

Manual DMG packaging derives the full release from the supplied app, validates
both bundle versions and its Settings version, and rejects mismatches before
tool invocation or output mutation. A checkout's version cannot relabel an
older app. The shell regressions simulate packaging tools; an actual macOS DMG
build is still required.

[Branch validation](flat-structure-candidate.md) records a passing 1,000-tab

## Integration review follow-ups

The native structure verifier now attempts observer cleanup, original-tab
restoration and fixture removal before persisting its report and success marker.
Cleanup and persistence failures prevent success without hiding a prior native
assertion failure. Four shipped-completion tests verify ordering and failures;
they do not simulate the 1,000-tab browser body.

A separate shipped-Flow regression starts with three existing pins and keeps
the exact focused middle-pin close control through adding, moving and removing
another pin. It verifies retained unaffected rows, native pin order, updated
ARIA positions/counts and one independent keyboard entry in each container.
Metadata changes required by pin membership are intentional, not redundant
writes. This supplements, rather than expands the claim of, the single-pin
sequence in the native structure fixture.

All 685 local regression tests and syntax checks pass for the integrated
candidate. Full native release staging is the next required verification.

## First combined staging: focus baseline correction

[34538488498](https://github.com/Ninnja10563/Fluxion-Browser/actions/runs/34538488498)
tested `7f3284f2df182202b34b27df13124213df3e60ef`. All 685 tests and every native
gate except structural reconciliation passed. About received actual anonymous
HTTP 200. Packaging and publication were correctly skipped.

The structural gate passed add/remove/move and the adjacent-swap check (one
relocation), then detected an unrelated `tabindex` write during pinning. A
shipped-Flow regression reproduced the cause: the fixture selected its next
tab while the previous control still had focus, so Flow intentionally retained
that existing keyboard entry. The fixture then moved focus without letting
selection reconcile the new owner. The next structural render correctly
updated the keyboard entry, inside what should have been a settled baseline.

The verifier now focuses its intended control before selecting its native tab,
waits for settling and explicitly requires selected-tab identity, exact control
focus and row `tabIndex === 0` before measurement. It records each baseline and
detailed unexpected mutations. No mutation exception was added, and product
focus behavior was not changed. The new regression proves both the old
sequence's deferred write and the corrected sequence's zero unrelated writes.
Corrected source still requires a fresh full native staging run.

## Second staging: native selection focus movement

[34539009954](https://github.com/Ninnja10563/Fluxion-Browser/actions/runs/34539009954)
tested `001c208b0aa63e8e6429984b5b00c8804f0e33aa`. The stricter first baseline
rejected setup before measuring any structural operation: selected owner 1
and `tabIndex` 0 were correct, but Gecko's tab switch had moved focus away from
the intended child control. This does not demonstrate a structural update
losing focus; no structural operation had started.

Setup now uses the shipped Flow Enter handler, which requests row focus after
native selection. It verifies selected-tab identity and keyboard entry after
settling, then focuses the exact child control and settles again before all
existing baseline and measurement assertions. It does not manufacture tab
indexes or whitelist mutations. A shipped-handler regression simulates native
focus movement before the animation frame and verifies the requested row focus,
followed by exact child focus and zero unrelated writes during pinning.

All 686 tests and the other native gates passed in that second run, except
About: its real anonymous GET received HTTP 403, remaining 0, reset
`1789082032` (2026-09-10 23:13:52 UTC). No release-discovery retry is allowed
before that deadline. No DMG was packaged or published.
