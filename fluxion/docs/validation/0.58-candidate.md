# Fluxion 0.58 stable selection candidate

This records the development and failed-run history behind published
[0.58](https://github.com/Ninnja10563/Fluxion-Browser/releases/tag/v0.58.0-preview.1).
See [release provenance](../../release/provenance/v0.58.0-preview.1.md) for the
exact successfully built and published assets. Earlier pending states below
describe their corresponding development stages, not current release status.

## Motivation

Ordinary TabSelect/TabMultiSelect events were classified as structural changes.
Flow cleared its row maps and replaced all pinned/tree children, recreating
rows, icons, controls and listeners even when tab topology was unchanged.
Mouse and keyboard activation also requested unconditional structural renders.
Existing 200-tab background-update and 1,000-tab search checks did not measure
ordinary repeated selection.

Workspace-active markers were additionally rewritten across the entire
workspace on each reconciliation, even when their saved values were unchanged.
Avoiding redundant writes must preserve authoritative SessionStore state and
repair of restored or inconsistent markers, not substitute a stale cache.

## Required verification

- Execute the shipped selection path in tests, including queued/coalesced
  selection, multi-selection, requested focus and structural fallback.
- Preserve active/selected/multi-selected indicators, independent pinned/tree
  roving stops, expanded-group and split active state, and collapsed-group
  active-page projections.
- Keep pointer-close stability and cross-workspace restoration behavior.
- Verify session marker transitions and repair without no-op writes.
- Use 1,000 actual Gecko tabs with repeated selections, asserting retained
  row/close-control identity and no unrelated DOM mutations. Cover real Flow
  activation handlers, multi-selection, pins, groups and splits separately.
- Record hosted event-to-frame timing without claiming display refresh rate
  or physical OS pointer latency.
- Require every existing native diagnostic and full release check, actual
  anonymous About discovery, packaging and exact artifact verification before
  publishing an unchanged tested DMG.

This milestone does not claim
full-roadmap completion or exhaustive performance/accessibility coverage.

## Local evidence and first diagnostic

All 615 regression tests passed on
`51cbae57f4bd025aec0f5aa6c2a3ab20475fb344`. The new tests execute the shipped
render/scheduler/activation functions together, retaining real core modules
with instrumented native boundaries. They cover 1,000 row/control identities,
coalesced updates, focus, group/split state and structural fallbacks. Marker
tests retain 1,000 authoritative reads while requiring only old/new writes and
zero writes for a repeated unchanged reconciliation.

Diagnostic [34525414361](https://github.com/Ninnja10563/Fluxion-Browser/actions/runs/34525414361)
passed row/control identity and zero unrelated/no-op/structural mutations on
its first selection, then failed a combined focus/scroll assertion. That single
48.16 ms sample is not a complete performance result. The original fixture
assumed URLbar focus would survive switching to a never-focused destination.

Mozilla's pinned
[tabbrowser focus implementation](https://github.com/mozilla-firefox/firefox/blob/FIREFOX_155_0_1_RELEASE/browser/components/tabbrowser/content/tabbrowser.js)
stores and restores focus per tab, including intentionally blurring the URLbar
when its destination has no saved URLbar focus. The verifier is being corrected
to observe that native destination behavior separately, then establish actual
per-tab URLbar focus through ordinary selection/focus before requiring strict
retention during repeated measurement. It will retain identity, mutation and
scroll assertions and record focus/scroll details rather than combine them in
an unexplained failure. No product focus behavior is changed for this fixture.

A complete passing diagnostic and full release staging remain required; no
failed diagnostic artifact can be promoted.

## Second diagnostic: native multi-selection event target

Diagnostic [34526343734](https://github.com/Ninnja10563/Fluxion-Browser/actions/runs/34526343734)
on `7475b1e622a648590599633219f3103c93ab1089` passed all 30 measured ordinary
selections with no unrelated, redundant-attribute or row-structural mutations.
The cold destination correctly received native browser focus; all primed
destinations retained URLbar focus, and Flow remained at scroll position 400.
The window was not OS-active, so this does not establish foreground OS input
latency or focus behavior.

The subsequent native multi-selection assertion exposed a real integration bug:
Gecko dispatches `TabMultiSelect` on `gBrowser`, whereas Flow subscribed only on
the tab-container descendant. Native changes outside the custom row handler
could therefore leave Flow indicators stale. The fix subscribes at the actual
native event target; a regression test must execute the shipped subscription
wiring rather than manually call its scheduler. The native assertion remains
required, with individual mismatch details retained for future failures.

## Third diagnostic: independent keyboard entry points

Diagnostic [34526805335](https://github.com/Ninnja10563/Fluxion-Browser/actions/runs/34526805335)
on `1286b09142f6c4e8f22ab5c7a4985cb07ab6f9af` passed ordinary selection,
native multi-selection, Gecko-routed row clicks and the shipped Enter handler.
After pinning a tab, it rejected a legitimate `tabindex` change on the tree's
previous keyboard entry point when selection returned from pinned tabs.
Pinned tabs and the ordinary tree must retain independent entry points; the
old tree entry is not necessarily the previously selected pinned tab.

The verifier must allow only the exact snapshotted prior destination entry's
`tabindex="0"` to `-1` transition when the selected destination becomes its new
entry. It must still reject any other attribute/content write on that row,
redundant writes, row replacement, or multiple keyboard entry points. This is
a fixture correction, not a product behavior change.

## Passing selection diagnostic

The complete selection gate passed in diagnostic
[34527297790](https://github.com/Ninnja10563/Fluxion-Browser/actions/runs/34527297790)
on `584c45cc55a8760679213708fc493a07487ea201`, after all 617 local regressions
passed. All 1,000 native rows and close controls retained identity through 30
ordinary selections and native multi-selection. No unrelated row writes,
redundant attribute writes or structural row changes occurred. Routed row
clicks, DOM Enter, independent pinned/tree entries, expanded/collapsed groups
and native stacked-split active markers passed too.

Hosted selection-to-first-frame timing was p50 18.38 ms, p95 27.35 ms and maximum
28.55 ms. These are 30 samples with 40 eager and 960 lazy fixture browsers,
not a foreground hardware-input benchmark or high-refresh-rate guarantee.
The cold focus policy and warm URLbar retention passed, with scroll remaining
at 400. The exact necessary previous-tree-entry demotion is separately recorded;
other writes to that row remain forbidden.

That diagnostic completed successfully: every native gate passed, including
real website authentication/upload, native macOS file selection, live tab
transfer, clean restart and abrupt crash recovery, private-data exclusion,
semantic Memory, Settings, Library and external opening. Full release staging
and exact DMG verification are still required before publication.

## Combined staging: concurrent fixture ownership and menu evidence

Combined staging [34529863235](https://github.com/Ninnja10563/Fluxion-Browser/actions/runs/34529863235)
on `826575e6fb33add242521ba267dd1e4897b15792` passed all 625 tests and the real
anonymous update request (HTTP 200). Packaging still correctly remained blocked
by two native gates: the broad browser fixture and the transfer fixture's OS
keyboard submenu phase. Transfer document/state/privacy checks and subsequent
clean/crash recovery passed; the menu failure is not evidence of lost tab data.

The broad fixture rendered grounded partial Memory evidence, but did not reach
its final async/grounding/organisation markers. Independent timed AI and page
command fixtures can take ownership of the same palette before that final
response. The production stale-response guard must remain intact; fixture
ownership needs sequencing and explicit stale/final diagnostics. The existing
evidence does not establish which competing timer invalidated this run.

The OS menu test observed its first four native leaf selections but failed to
open Move to Window after counting intervening submenu headers. Its driver
acknowledges key injection, not AppKit processing, and does not record those
headers' selection. Further diagnostics must record computed menu order and
per-key state, acknowledge observable leaf selections, and retain the actual
native submenu/open/escape/focus assertions.

Fixture hardening now waits for all enabled competing palette owners before
starting grounding, reports missing owners and stale/rejected/empty final
responses, and releases the organisation palette only after its visible
suggestion check succeeds. Native menu diagnostics record enabled item order
and per-key popup/focus state; expected leaf moves require a new trusted native
highlight event. Header event-loop settling is explicitly not counted as a
processed-key acknowledgement. All 631 local tests pass, including readiness,
timeout, delayed native-highlight, wrong-leaf and unopened-submenu regressions.
Production stale-result guards and every native release assertion remain.

## Successful full staging and publication

Full staging [34531228585](https://github.com/Ninnja10563/Fluxion-Browser/actions/runs/34531228585)
passed all 631 tests and every required native gate on
`16dfb49d0fd8bc71e47e53cb13f8040179327366`. Grounding, async-result safety and
organisation completed after fixture sequencing; both tab and group OS menu
navigation passed with the stronger expected-leaf acknowledgement. Actual
anonymous About discovery returned HTTP 200. Packaging and upload succeeded.

Final native selection evidence again retained 1,000 row/control identities
through 30 selections, with zero unrelated writes, no-op attributes or row
rebuilding. Hosted p50 was 18.30 ms, p95 34.77 ms and maximum 42.66 ms. The
40-eager/960-lazy fixture and background window focus scope do not establish
foreground physical-input latency or a high-refresh-rate guarantee.

The universal DMG and checksum were published unchanged from this successful
run, not from any failed diagnostic or earlier staging attempt. The full
roadmap remains in progress, including broader hardware/accessibility work
and Developer ID signing/notarization.
