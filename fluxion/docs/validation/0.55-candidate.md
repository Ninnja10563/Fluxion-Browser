# Fluxion 0.55 interaction candidate

This preserves development evidence, not release provenance. The candidate
subsequently passed full release staging and was published; see the
[0.55 release provenance](../../release/provenance/v0.55.0-preview.1.md).
Diagnostic workflows alone do not substitute for complete release staging.

## Flow menu and split activation

[Run 34515109475](https://github.com/Ninnja10563/Fluxion-Browser/actions/runs/34515109475)
passed on `72b472f94072d3067518a59291c635ae3ab5795a` with 573 regression tests.
Native verification opened tab and group context menus using macOS System
Events key codes, navigated to a real destination submenu item, cancelled with
Escape, and verified focus returned to the original Flow anchor. Initial
anchor focus was set by browser chrome; these were not physical hardware keys.
Every key was guarded by the exact owned application PID and active window.

The command-palette test activated the actual stacked-split command, chose a
tab through the picker, and checked the resulting native pair and orientation
after palette dismissal. Node tests separately cover stale targets, changed
selection, replaced rows, submenu closure, and avoiding focus theft.

## Workspace-name search and many-tab behavior

[Run 34516141860](https://github.com/Ninnja10563/Fluxion-Browser/actions/runs/34516141860)
passed on `e052b355d2807fb37a9d4fed08552ddbdaab4227`, with 574 regression
tests and every diagnostic native gate successful. The actual packaged browser
searched 1,000 fixture tabs (1,001 native tabs including the original page),
kept no more than 12 visible results, retained input focus, and used current
tab titles, URLs, groups, and workspace metadata. Renaming a real workspace
between palette openings made its new visible name searchable and removed the
obsolete name from matching results. The stacked-picker proof also passed.

The hosted Mac measured 20 DOM-input-to-next-animation-frame samples: median
26.506 ms, 95th percentile 189.274 ms, maximum 302.676 ms. Samples include live
metadata/structural updates, not only warmed query changes. This is a bounded
regression check, not evidence of continuous 120 Hz rendering or physical-key
input-to-display latency. The 500 ms p95 / 1,500 ms maximum CI ceilings are not
product performance targets; slower structural-update samples remain work to
improve. The separate existing 200-tab Flow update assertions remain required.

Search ranking is compared against the previous full-sort algorithm across
1,100 records, exact/fuzzy/accented queries, stable ties and bounded limits.
`node fluxion/scripts/benchmark-tab-search.cjs` provides a reproducible
CPU-only comparison in identical Node VM contexts. It does not measure Gecko
paint, macOS responsiveness, startup, battery use, or total browser memory.

The successful native diagnostic also verified the real macOS file picker,
Library menus, authentication and transfers, local semantic Memory, tab
adoption, and clean/SIGKILL recovery. These results apply to its exact source,
not to subsequent unverified edits.

## Live General and Appearance settings

Source `548af8a597f04b550e81c1b3b9e1233ca0598f32` includes cross-window and
toolbar preference synchronization, preserving an unsaved homepage draft and
pending select edits. It also includes the clear-data dialog-verifier readiness
and exception-reporting correction. All 582 local tests passed without skips.
[Native run 34516652338](https://github.com/Ninnja10563/Fluxion-Browser/actions/runs/34516652338)
passed every diagnostic gate on that exact combined source. The required
`live-general-appearance-and-homepage-draft-verified` marker and both new
cross-window check entries are present in its Settings report.

The expanded Settings verifier retains the existing shortcut checks and adds
real packaged two-window Settings controls, DOM activation of the shipped
sidebar cycle button, remote General/Appearance edits, actual DOM draft focus,
draft preservation, commit propagation, and subsequent external updates. Its
script-created control/input events are explicitly distinguished from OS input.

The same run repeated the 1,000-tab search proof with median 29.823 ms,
p95 96.995 ms and maximum 103.497 ms across 20 samples. The difference from the
earlier run illustrates hosted-runner variability, not a separately measured
optimization. Both raw reports remain in their linked workflow logs.
