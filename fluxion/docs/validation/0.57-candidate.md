# Fluxion 0.57 Settings layout candidate

This is development evidence, not release provenance. The latest published
DMG is [0.56](https://github.com/Ninnja10563/Fluxion-Browser/releases/tag/v0.56.0-preview.1).

## Motivation and scope

The 0.56 sidebar release established actual Appearance and Library bounds in
320 pixels of remaining space, but did not prove every Settings section fits.
Review found fixed workspace grid minima, oversized permission rows, shortcut
min-content widths and unbroken text that could require horizontal scrolling.
An older viewport rule also hid permission expiry, which is meaningful state.

This candidate addresses Settings sections together. Compact container-aware
layouts should preserve every control and the underlying browser operation,
use wrapping or additional rows rather than hidden information, and retain
ordinary wide-window layout. It also gives repeated site-reset controls
distinct accessible names.

## Required evidence

- Full shipped-script permission action tests, including distinct labels and
  targeted service calls, alongside existing Settings and workspace tests.
- Original native accessible-name and help-text checks retained.
- Packaged Gecko geometry at 320 and 600 pixel Settings-root widths across
  all ten sections, including populated Workspaces and Permissions.
- Visible controls fit horizontally and the main reading surface does not
  require horizontal scrolling. Permission expiry remains rendered.
- Create and rename a workspace through actual narrow Settings controls.
- Captured real narrow layout for visual inspection.
- Every existing native release check, packaging, and actual anonymous About
  discovery must still pass before unchanged tested bytes can be published.

No native result or release success is claimed yet. DOM-driven geometry and
action checks are not physical OS input or exhaustive assistive-technology
validation, and no high-refresh-rate or full-roadmap completion claim is made.
