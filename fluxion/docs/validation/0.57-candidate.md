# Fluxion 0.57 Settings layout candidate

This records development evidence. Version
[0.57 is published](https://github.com/Ninnja10563/Fluxion-Browser/releases/tag/v0.57.0-preview.1);
its exact build and assets are recorded in
[release provenance](../../release/provenance/v0.57.0-preview.1.md).

## Motivation and scope

The 0.56 sidebar release established actual Appearance and Library bounds in
320 pixels of remaining space, but did not prove every Settings section fits.
Review found fixed workspace grid minima, oversized permission rows, shortcut
min-content widths and unbroken text that could require horizontal scrolling.
An older viewport rule also hid permission expiry, which is meaningful state.

This candidate addresses Settings sections together. Compact container-aware
layouts should preserve every control and the underlying browser operation,
use wrapping or additional rows rather than hidden information, and retain
ordinary wide-window layout. It also gives repeated site-reset controls
distinct accessible names.

## Required evidence

- Full shipped-script permission action tests, including distinct labels and
  targeted service calls, alongside existing Settings and workspace tests.
- Original native accessible-name and help-text checks retained.
- Packaged Gecko geometry at 320 and 600 pixel Settings-root widths across
  all ten sections, including populated Workspaces and Permissions.
- Visible controls fit horizontally and the main reading surface does not
  require horizontal scrolling. Permission expiry remains rendered.
- Create and rename a workspace through actual narrow Settings controls.
- Captured real narrow layout for visual inspection.
- Every existing native release check, packaging, and actual anonymous About
  discovery must still pass before unchanged tested bytes can be published.

DOM-driven geometry and action checks are not physical OS input or exhaustive
assistive-technology
validation, and no high-refresh-rate or full-roadmap completion claim is made.

## First diagnostic

All 601 local regression tests passed. Diagnostic
[34522457085](https://github.com/Ninnja10563/Fluxion-Browser/actions/runs/34522457085)
ran source `bea79c92077a90fd5f573dcd526906d799488f25`. Its original native
accessible-name checks passed, as did 320 pixel General/Appearance/Tabs
geometry. The next fixture failed while awaiting a 33-character renamed
workspace: the real model correctly limits names to 32 characters. The
fixture now uses a valid shorter name and asserts the field limit before
submitting. No product behavior was weakened to accommodate the fixture.
This run finished with only the fixture failure above; all other native gates
passed. Its failed artifact is not eligible for promotion.

## Passing diagnostic

[34522929708](https://github.com/Ninnja10563/Fluxion-Browser/actions/runs/34522929708)
passed on `60ca502ceea64e02b2087770685b8d9df9cdd296`: all 601 regression tests
and every native gate. The Settings report measured all ten sections at both
320 and 600 pixel root widths, covering 184 rendered controls. Main scroll
width equalled client width in every section, including populated Workspaces
and Permissions. Permanent, session and timed permission expiry text remained
visible at both widths, and Gecko exposed the origin/context-specific site
reset name through its accessibility service.

The narrow form created and renamed a workspace, and the current workspace's
long name wrapped in the summary. Two independent screenshot inspections found
the actual field, Add action, workspace identity, symbols, colours and wrapped
reordering/deletion actions readable and reachable without page-level
horizontal scrolling. Long editable names retain normal single-line input
scrolling. The report and screenshot are artifact `10170426218`,
`Fluxion-settings-layout-diagnostic`.
